# Workshop 1 Exercise Worksheet: Modernizing APIs for AI Agents: From OpenAPI to MCP

**Duration:** 45 minutes  
**Profile:** `w1`  
**Prerequisites:** Docker Engine 24+ with Compose v2, Python 3.12 with `venv` and pip, free port 9080. Run launcher commands in Bash on Linux/WSL; Python clients also work on macOS.

---

## Exercise Objectives
1. Connect to the standalone APISIX MCP Gateway endpoint over Streamable HTTP.
2. Observe how naive OpenAPI-to-MCP generation exposes excessive enterprise capabilities.
3. Curate the exposed OpenAPI specification down to safe Tier-1 customer support read operations.
4. Verify the **Gate 3 Loopback Invariant**: prove that calling tools through MCP still enforces downstream API authorization and blocks unauthorized access.

---

## Before the session: prepare the Python client

Run these commands from the repository root before the timed exercise:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install httpx==0.27.0
.venv/bin/python -c "import httpx; print(httpx.__version__)"
```

This is the minimal setup for the W1 participant client. The Python script sends
MCP requests to APISIX and prints JSON or SSE responses; it does not run the MCP
server. Docker dependencies do not install packages into your host Python.
Using `.venv/bin/python` selects the correct interpreter without activation.

If you also use `scripts/workshop` verification/reset or W2–W4 scripts, complete
the [full Python setup](../../docs/workshops/participant-infra-guide.md#step-23-set-up-python-virtual-environment-for-workshop-clients-verification--tests)
instead. If Ubuntu/Debian reports that `ensurepip` is unavailable, install the
`python3-venv` package matching your Python version and rerun environment creation.

## Step 5: Capability Review and Q&A (Minutes 40–45)

Inspect `workshops/w1/checkpoints/completed/openapi-curated.json`.
Compare it with `workshops/w1/checkpoints/initial/openapi-broad.json`.

Notice:
- Risky mutation endpoints (`/payments`, `/incidents`, `/admin`) are removed.
- Tool names and parameter descriptions are clear and concise.
- This checkpoint has no `readOnlyHint` annotation. Descriptions and hints do
  not enforce authorization; catalog exclusion and downstream controls do.

Explain one removed operation, one improved description, and the actual
curated discovery/authorization evidence. The broad tool count changes with the
served API; record the current count rather than expecting a fixed number.
