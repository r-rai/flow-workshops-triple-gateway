# NovaBank final implementation audit — 2026-10-03

**Verdict: substantial remediation is verified, but the platform does not yet support the handoff's “fully re-verified / all findings resolved” claim.** A delegated anti-self-approval bypass remains. W1 does not enforce its curated contract, W1 startup verification fails reproducibly, preflight falsely passes failed digest inspections, A2A completion does not validate settlement, and deployed API telemetry is broken.

Reviewed branch `feat/implement-novabank-platform`, HEAD `c54a26902e508ca9c674059bbbd325895864959f`, on Linux VPS `vmi3355051`. The working tree was clean at entry. Findings below concern that implementation; only this report and [fresh audit artifacts](2026-10-03-novabank-final-audit-evidence/) were added. Existing reports and implementation files were not edited.

## Findings and recommendations

1. **High — exchanging a delegated manager token bypasses delegated anti-self-approval.** [oauth.py](../../src/api/routes/oauth.py), lines 195–200, wraps the original actor in a nested `act` and puts the manager's own subject in the outer `act.sub`. [security.py](../../src/core/security.py), line 37, reads only the outer actor, so [approvals.py](../../src/services/approvals.py) no longer sees the requester in the delegation chain. In a temporary database, a legitimate lab-issuer-signed manager token delegated by the proposal requester received **403 before exchange**, exchanged successfully, then approved the same proposal with **200 after exchange**. The resulting actor chain was `manager → requester`; the nested requester was ignored. This is a provenance/authorization defect, not signature forgery or viewer-role escalation. Normalize and validate the complete delegation chain for approval authorization, preserve its meaning through repeated exchanges, and add a regression that must remain 403 before and after exchange. Evidence: `delegation_approval_after_exchange` in [isolated-controls.json](2026-10-03-novabank-final-audit-evidence/isolated-controls.json).

2. **Medium — W1's exclusion check does not prove contract curation.** The updated [runner](../../workshops/w1/rehearsal_w1.py) loads the completed contract and confirms two paths, but the gateway still builds its catalog from the full backend `/openapi.json` ([W1 routing](../../docker/apisix/apisix-w1.yaml)). It advertises **22 tools**, including payment execution and admin reset. The runner tests `delete_customer_account`, a name absent from the broad catalog, so this establishes rejection of an unknown name only. An independent, read-only call to the actually advertised `list_payments_api_v1_payments_get`, which is outside the curated account/case contract, succeeded with **HTTP 200 and downstream status 200**. Make the curated checkpoint executable, compare its operation set with the generated catalog, and invoke actual excluded broad operations under that checkpoint. Save the curated paths and exclusion responses in rehearsal JSON; the current runner prints these checks without saving them. Evidence: [W1 supplement](2026-10-03-novabank-final-audit-evidence/confirmation-run/w1-supplement.json) and [rehearsal log](2026-10-03-novabank-final-audit-evidence/confirmation-run/w1-rehearsal.log).

3. **Medium — Jaeger telemetry is nonfunctional, while W4 reports success.** Both fresh W4 rehearsals reported **0 traces / 0 spans** and exited 0. The deployed API logs `OTel setup skipped or failed: No module named 'pkg_resources'`; a network-disabled helper using the same API image reproduced that import error through OpenTelemetry's instrumentation dependency. Telemetry is configured enabled. After an authorized MCP account read with explicit trace context and a 12-second export window, Jaeger returned **404, trace not found**, no API traces, and only its own service. [W4 lines 394–405](../../workshops/w4/rehearsal_w4.py) fabricate fallback service names and never assert trace/span counts. Resolve the instrumentation packaging dependency, instrument the promised boundaries, and assert a shared trace with the required spans and parent relationships. Evidence: [telemetry-import.log](2026-10-03-novabank-final-audit-evidence/telemetry-import.log), [API logs](2026-10-03-novabank-final-audit-evidence/confirmation-run/w4-api-logs.log), [authorized trace probe](2026-10-03-novabank-final-audit-evidence/trace-readonly.json).

4. **Medium — W1 readiness still produces a reproducible immediate verification failure.** On both independent profile transitions, `switch w1` exited 0 but the next `verify w1` exited **1: MCP init failed: 500**. The rehearsal and a subsequent verification passed. Captured APISIX errors show connection refusal fetching the backend OpenAPI specification. The installed pinned plugin caches failed specification fetches for five seconds; readiness probes can succeed on one gateway worker while another retains a failed fetch. The CLI also probes MCP while backend readiness is still false. Gate startup on backend/spec readiness before warming MCP, and verify real tool discovery and a downstream tool result. Evidence: [first failure](2026-10-03-novabank-final-audit-evidence/w1-verify.log), [confirmation failure](2026-10-03-novabank-final-audit-evidence/confirmation-run/w1-verify.log), [gateway errors](2026-10-03-novabank-final-audit-evidence/confirmation-run/w1-gateway-errors.log), [passing recheck](2026-10-03-novabank-final-audit-evidence/confirmation-run/w1-verify-recheck.log).

5. **Medium — preflight's digest validator fails open.** The healthy host's preflight passes, and independent checks confirm all five installed third-party digests and Compose references match the manifest. However, [scripts/workshop](../../scripts/workshop), lines 112–142, ignores unsuccessful image inspection, suppresses Python errors with `|| true`, and treats everything except a literal `Digest mismatch` string as success. In a temporary copy, **all image inspections failing** and a **malformed manifest** each yielded exit 0 and “Pinned digests verified.” Propagate the validator's exit code; require every expected image, nonempty digest, and valid manifest entry. Evidence: [preflight-faults.json](2026-10-03-novabank-final-audit-evidence/preflight-faults.json). Third-party deployment pinning is now fixed; this remaining failure concerns validation reliability.

6. **Medium — A2A completion accepts fabricated settlement results.** Owner/scope controls work for the tested unrelated agents. However, [a2a.py](../../src/api/routes/a2a.py), lines 150–161, authorizes an owner or the global executor, then stores arbitrary result JSON and marks the task completed. A synthetic task owner with only `api:a2a:tasks` supplied `payment_id: nonexistent-audit-payment` and `status: SETTLED`; the backend returned **200 / completed**, with no corresponding payment. The W4 runner similarly attaches an existing 150,000-unit payment to a separately delegated 50,000-unit task without validating their relationship. Validate payment existence, successful settlement, proposal/approval, amount, destination, and task association; enforce terminal-state transitions. Task submission still does not dispatch a PaymentsAgent. Evidence: [W4 supplement](2026-10-03-novabank-final-audit-evidence/confirmation-run/w4-supplement.json).

7. **Remaining delivery/documentation gaps.** Gate 1 now enforces a simple process-local synthetic token budget; an isolated exhausted-budget test returned 429. It still always constructs a replay response: setting `USE_REPLAY_FIXTURES=false` changes the model label to `gpt-4o-mini` while returning `[REPLAY]` without calling a provider. This does not establish the facilitator guide's live-provider fallback claim. W3 still describes hardcoded diagnosis as simulated LangGraph. Its runner deletes Temporal's database while the server is running during setup and uses graceful `docker stop` for “crash”; the supplementary SIGKILL check below supplies stronger recovery evidence, but the destructive setup should be explicit and stop writers first. Reconcile these simplifications with the approved delivery plan. Correct that plan's stale “not implemented yet” status, the handoff's “all nine digests pinned” wording, its “>6 GB free host RAM” assertion, and its blanket verification status. The manifest accurately distinguishes five pinned third-party images from four built image tags. Direct build requirements are now version-pinned, but base image/transitive dependency coordinates are not fully locked. Evidence: [isolated controls](2026-10-03-novabank-final-audit-evidence/isolated-controls.json) and the referenced implementation/guide files.

## Memory, existing services, and Windows status

**Observed memory containment passes the 6 GB VPS operating budget.** Across **138 fresh Docker samples**, the nine-container sampled maximum was approximately **995,047,244 bytes = 995.05 decimal MB = 948.95 MiB**. Docker's displayed active working-set figures are rounded; these totals are approximate, not high-resolution RSS measurements. Recomputing the original 80 saved samples independently confirms the historical **951,021,733 bytes = 951.02 MB = 906.97 MiB**. The historical number is accurate, but should not be described as the current maximum or a sustained-load upper bound. All nine runtime limits are applied and sum to **3 GiB**. Minimum observed host `MemAvailable` was **5.80 decimal GB**, so the handoff's “>6 GB free” claim is unsupported. Sustained sessions, every startup transient, and two simultaneous fallback runs remain unbenchmarked. The earlier 750 MB target is also not met by these samples.

**Existing VPS services were unharmed by the audit.** `caddy`, `portainer`, `uptime-kuma`, and `dozzle` retain identical IDs, start times, restart counts, running/health states, and port bindings before the first run and after confirmation/restoration. Direct HTTP checks returned **308, 200, 302, 200**, respectively; Uptime Kuma remains healthy. They were never stopped, restarted, or reconfigured. Evidence: [memory-and-host.json](2026-10-03-novabank-final-audit-evidence/memory-and-host.json), raw sample files, and protected before/after snapshots.

**Windows 11 / WSL2 5 GB RAM remains correctly marked unverified** in the manifest, handoff, facilitator guide, and compatibility report. This Linux audit provides no Windows performance result. Retain that status and benchmark capped native Windows participant hardware before claiming validation.
